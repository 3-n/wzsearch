## 4. Invariants – do not break these

1. **Sources first.** Every record keeps `sources[]` → file (original URL + mirrored copy + sha256) → sheet/row (or
   GUNB line numbers) → `raw` cells as published. Corrections are never silent: they add a `warnings[]` entry and
   keep the original spelling for display. Nothing in the source is dropped without a counted, documented reason
   (template rows, note rows, other-district BAiPP rows) – `sources.json` shows declared vs parsed counts.
2. **Stable ids.** Record ids are permalinks (`wz-2026-15`, `wz-am-2026-95`, `ws-6730-2026-29`,
   `pb-st-mz-pa-2026-29594`). Never change the id scheme for existing records; new datasets get their own namespace.
3. **Determinism.** Stable ordering everywhere; `generated_at` changes only when the five JSON/GeoJSON documents
   change; `SITE_URL` affects only CSVs, feed and report. A rebuild that finds nothing new writes nothing.
   `test.yml` enforces this (offline rebuild must equal the committed data). Check with
   `uv run python -m pipeline.build --offline` → "no changes".
4. **Additive schema.** `records.json` / `permits.json` / `sources.json` may gain fields; renames/removals need both
   sides changed together and `docs/DATA_MODEL.md` updated. Every field may be null; the UI must degrade.
5. **CSV columns live in two places** – `pipeline/export.py CSV_COLUMNS` and `site/js/csv.js CSV_COLUMNS`, with the
   same formula-injection guard (`escape_cell` / `escapeCell`). A pytest parses csv.js and fails if they differ.
   The browser export and `records.csv`/`permits.csv` must agree cell for cell.
6. **Privacy.** Natural-person names are redacted (`normalize.redact_persons`); company names are kept; GUNB designer
   columns (`projektant_*`) never reach records, UI or CSV (they remain only in the byte-exact mirrored extract).
7. **Untrusted data in the browser.** Data is inserted with `textContent`/attributes only, never `innerHTML`; URLs
   from data pass `safeUrl()` (`site/js/dom.js`). Keep it that way.
8. **No build step, relative URLs only, hash routing** – the site must keep working from any sub-path
   (`node tests/e2e/server.mjs --base=/wzSearch/` reproduces GitHub Pages project sites). Every new module in
   `site/js/` must be added to the `modulepreload` list in `index.html` (`tests/js/index-html.test.mjs` checks it).
9. **Politeness.** ≤ 2 requests/s per host (crawler delay 0.5 s; GUGiK ULDK/UUG likewise). GUNB: one conditional GET
   per ZIP. Never parallelise against the source sites.
10. **Exit codes.** 0 ok · 3 a live source failed and the previous data was used (district index down, a monthly
    page served without its file list, a previously parsed file now unreadable, GUNB format change) · 1 nothing
    could be built (e.g. an edited committed RWDZ extract). CI commits and deploys only on 0.

## 6. Testing – what covers what

* **pytest** (`tests/test_*.py`): crawler on stripped real HTML; parser on real workbooks of every layout against an
  independent oracle; normaliser/classifier on the real corpus in `data/raw`; RWDZ filter on real GUNB lines (the ZIP
  byte-exactness check runs with `RWDZ_VERIFY_ZIPS=1` when the ZIPs are present); geocoding with fake ULDK/UUG;
  end-to-end `run_build` on a throw-away project; determinism; CSV parity with csv.js; real-data reconciliation checks.
* **node --test** (`tests/js/`): the pure modules (url, filters, search, csv, kinds, lazy, format, card, detail, map
  helpers, sources, index.html hints, dev server).
* **e2e** (`tests/e2e/smoke.mjs`): desktop/mobile × light/dark, robustness (missing files, slow network, bad
  permalinks), permits opt-in/lazy load, keyboard flows, 320 px overflow worst cases, WebKit group. `--only=<group>`
  runs one group. Fixture data lives in `tests/fixtures/site-data/` (small, partly synthetic, clearly labelled).
* After any data-affecting change: offline rebuild → "no changes" (or an explained diff), then `npm run e2e:real`.

## 7. Operating the data (monthly cycle)

`update.yml` runs daily at 06:00 UTC on the 9th–16th (the office publishes around the 10th) and weekly otherwise:
crawl → GUNB check → build → tests → commit changed data → deploy `site/`. After a run with new data, skim
`data/report.md`:

* **Warnings / new typos.** New street misspellings → add to `STREET_TYPOS` (or `STREET_CANONICAL` for variants of
  one street) in `pipeline/normalize.py`, rebuild offline, check the street filter.
* **"Category/count not detected"** on a monthly page → a new heading wording; extend the detection in `crawl.py`.
* **New spreadsheet layout** → see playbook 8.1.
* **RWDZ review list** ("unkept cases with Praga-Południe signs") → check each in ULDK; confirmed register errors go
  into `rwdz.UNIT_FIXES` with a comment (never automatic).
* **Exit 3 in CI** → nothing was deployed; the previous site stays. Look at the run log: district site down (retry
  later), a maintenance page (retry), a lost file (check the source page by hand), or a GUNB format change (adapt
  `rwdz.py`, the header check fails loudly by design).
* **Numbers that never appear in any list** (report section) are worth asking the office about (`BACKLOG.md` §2).

## 8. Playbooks for common changes

### 8.1 A new spreadsheet layout appears
1. Copy the workbook into `tests/fixtures/xlsx/` (or `tests/fixtures/baipp/xlsx/`) – real file, nothing invented.
2. Extend header classification in `pipeline/parse.py` (`classify_header`, layout detection); add a parse test with
   the expected rows.
3. `make data-offline`; check `data/report.md` (parsed vs declared counts) and a few records in the UI's
   "Dane w źródle" view.

### 8.2 A new tag / classification rule
`pipeline/classify.py`: add to `TAGS` (label, description, group `funkcja` or `roboty`) and a rule; add cases to
`tests/test_classify.py`; rebuild offline. The UI picks up tags from `records.json → tags` (hidden when empty).
Renaming a slug breaks old `typ=` links (they are dropped silently by `sanitizeFilters`).

### 8.3 A new filter / facet
Data side: put the value on every record (additive field, documented in DATA_MODEL v2) and, for labels, a
dictionary in `records.json` (pattern: `datasets`, `issuers`, `outcomes`). UI side: predicate + facet counting in
`site/js/filters.js` (single-pass `evaluate`), URL parameter in `site/js/url.js` (+ `sanitizeFilters`), chip text in
`site/js/active.js`, panel in `site/js/views/filters-panel.js`; document the parameter in FRONTEND.md's URL table; add
unit tests and an e2e check.

### 8.4 A new record field shown in the UI
Pipeline: add to `RECORD_FIELDS` in `build.py` (key order is part of determinism), fill it, document it. UI: render
it in `site/js/views/detail.js` (facts) and/or `components/card.js`; only text insertion. If it should be searchable,
add it to the folded search document in `data.js` with a weight.

### 8.5 Changing CSV columns
Change **both** `pipeline/export.py CSV_COLUMNS` and `site/js/csv.js CSV_COLUMNS` (same order, same cell rules),
the CSV section of DATA_MODEL.md and FRONTEND.md, and both test suites; rebuild; check browser export = pipeline CSV.

### 8.6 A new data source / dataset
Follow how BAiPP and RWDZ were added (DATA_MODEL "v2 extension" + the two "as implemented" subsections): own
`dataset` key in `DATASETS`, own id namespace, `sources[]` that point to a mirrored, hash-checked copy, its own
Sources tab (`site/js/views/sources.js` lays tabs out by dataset key), facet labels from dictionaries, research notes
in `docs/research/`. Decide default visibility (opt-in like permits if it would swamp the planning records).

### 8.7 A new page / route
Router in `site/js/main.js`, hash parsing in `site/js/url.js`, view module in `site/js/views/`, nav link in
`index.html`, modulepreload entry, e2e check (light/dark, phone width, keyboard).

### 8.8 Map / basemap
`site/js/config.js → BASEMAP` (OSM standard tiles today; CARTO now needs a key) and `WMS` (GUGiK orthophoto and
parcels). Attribution must stay visible. Marker shapes/colours per kind: `site/js/components/map.js` + CSS tokens.

### 8.9 Publishing
GitHub Pages: README "Deploying to GitHub Pages" (create repo, Pages source "GitHub Actions", allow Actions to push,
fill `REPO_URL`/`ISSUES_URL`, run "Update data & deploy" once). Other hosts: `SITE_URL=https://… make data`, upload
`site/`. Make `og:image` absolute once the URL is known. Deployed size ≈ 19 MB (`site/`), far below Pages limits.

## 11. Gotchas and lessons learned

* `npm run e2e` overwrites `tests/e2e/output/` with fixture screenshots – run `e2e:real` last before looking at them.
* Two processes must not write `site/data` at the same time (an e2e run on real data reads it mid-rewrite and fails).
* Python's `http.server` on macOS occasionally resets a module request – use the Node server (`make serve` does).
* `node --test tests/js/` (directory form) fails on Node 25 – the package script uses the glob `'tests/js/*.test.mjs'`.
* `uv run pytest -q` prints no summary (addopts already has `-q`); use `uv run pytest`.
* ULDK only knows *current* parcels; ~10% of ids in old decisions are subdivided/merged. The obręb's 4-digit ULDK code
  drops the zone digit (0203 exists in Mokotów and Praga-Południe) – always restrict probes by zone (`OBREB_ZONES`).
* Monthly page period comes from the page **title**, not the slug (`styczen-2022-r` is titled "Grudzień 2021 r.").
* GUNB regenerates all ZIPs nightly (new ETag) even when nothing changed; the build commits nothing then. Its
  download page says the separator is `#` – it is `;`.
* Overpass (OSM) is sometimes over capacity; areas are cached and rebuilt only on demand.
* The research material from the first session (downloaded HTML, scratch scripts, audit screenshots) lived in a
  temporary scratch directory and is gone; everything durable is in `docs/research/`, the tests' fixtures and
  `data/report.md`.
* How this was built: a lead plus parallel agents with strict file ownership, followed by independent audits whose
  findings were adversarially re-verified before fixing (73 confirmed, 70 fixed). Keep that discipline for big
  changes: one owner per file set, the data contract as the coordination point, verify on real data.
